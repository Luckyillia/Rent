# Обновление: занятость машины + гибкие тарифы по датам + отступы скелетонов

Пакет кладётся поверх файлов из предыдущих архивов
(`forward-auto-rent-supabase-update.zip`,
`forward-auto-rent-booking-stages-update.zip`) — заменяет часть файлов
и добавляет новые.

## Что изменилось

### 1. Скелетоны больше не "задраны" к хедеру

На страницах машины и брони скелетон-заглушка не учитывала место, которое
реально занимают `Breadcrumbs` (28px сверху + строка текста + 28px снизу,
~76px) — во время загрузки контент выглядел заметно выше и теснее, чем
после загрузки. Добавлена переменная `--crumbs-block-height` в
`src/index.css`, применена в `CategoryPage.css`, `VehiclePage.css` и
(отсутствовавшей раньше) `BookingPage.css`. См. `PATCH-CSS-VARS.md`
для двух точечных строк в файлах, которые не пересылаются целиком.

### 2. Машину нельзя забронировать второй раз, пока она в аренде

- В `vehicles` добавлено поле `is_rented` — сервер сам держит его в
  синхроне: `create-rental` ставит `true` при успешной заявке,
  `admin-api` пересчитывает его при смене статуса заявки или удалении
  (занята, если у машины осталась хоть одна заявка со статусом
  `active`).
- На странице машины (`/car/:id`) кнопка «Забронировать» становится
  серой неактивной кнопкой «Недоступно» с поясняющей подписью, если
  машина занята.
- Страница брони (`/book/:id`) при прямом заходе на занятую машину
  показывает то же сообщение вместо формы.
- `create-rental` также сам отказывает (409), если машину успели
  забронировать между открытием страницы и отправкой формы.

### 3. Гибкие тарифы по срокам аренды вместо жёсткого «сутки / неделя»

- Новая таблица `vehicle_price_tiers`: у машины может быть 0 тарифов
  (тогда работает как раньше — `price_day` на каждые сутки) либо любое
  количество диапазонов `от X до Y дней → цена/сутки` (`Y` можно
  оставить пустым — значит "и больше").
- Форма брони (`/book/:id`) вместо переключателя «Сутки / Неделя»
  теперь просит даты «С какой — По какую» и сама показывает разбивку:
  «N суток × цена/сутки = итог», подбирая тариф под введённое число
  дней.
- Страница машины показывает список тарифов вместо старого
  переключателя.
- В админке (`/admin` → Машины) под стейджами появился блок «Тарифы по
  срокам аренды» — можно добавлять/удалять строки `от / до / ₽ в сутки`
  прямо там, это полностью в вашей воле, никакого хардкода.
- В админке (`/admin` → Аренды) вместо «Период» показываются реальные
  даты аренды и количество дней.

## Что нужно сделать у себя

### Шаг 1 — обновить базу

В SQL Editor выполните:

```
supabase/migration_availability_pricing.sql
```

### Шаг 2 — передеплоить функции

```bash
supabase functions deploy create-rental --no-verify-jwt
supabase functions deploy admin-api --no-verify-jwt
```

(`admin-login` не менялась.)

### Шаг 3 — заменить файлы фронтенда

Скопируйте поверх текущих:

```
src/api/vehicles.js
src/api/rentals.js
src/pages/BookingPage/BookingPage.jsx
src/pages/BookingPage/BookingPage.css
src/pages/VehiclePage/VehiclePage.jsx
src/pages/VehiclePage/VehiclePage.css
src/pages/AdminPage/VehiclesAdmin.jsx
src/pages/AdminPage/RentalsAdmin.jsx
```

Добавьте новые:

```
src/utils/pricing.js
src/components/PriceTiers/PriceTiers.jsx
src/components/PriceTiers/PriceTiers.css
```

Добавьте содержимое `src/pages/AdminPage/AdminPage.append2.css` в конец
существующего `src/pages/AdminPage/AdminPage.css`.

Примените две точечные правки из `PATCH-CSS-VARS.md`
(`src/index.css` + `src/pages/CategoryPage/CategoryPage.css`).

### Шаг 4 — перенести существующие тарифы (если у вас уже была цена
за неделю)

`price_week` больше нигде не используется на публичных страницах —
она осталась в базе и в форме админки просто "на всякий случай"
(необязательное поле). Если хотите сохранить старую логику "неделя
дешевле", заведите для каждой машины тариф `от 7 дней, ₽/сутки` в
блоке «Тарифы по срокам аренды» — цена за сутки там ниже, чем в поле
«Цена / сутки» выше него.

### Шаг 5 — перезапустить dev-сервер

```bash
npm run dev
```

## Если заявки на бронь уже были с полем `period`

Миграция удаляет колонку `period` из `rentals` — если она вам зачем-то
нужна в исходном виде, сохраните данные (`select * from rentals;`)
перед выполнением миграции.
