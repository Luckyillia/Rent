# Миграция на Supabase + Cloudinary + Админка

Этот пакет — набор файлов для замены в существующем проекте
`forward-auto-rent`. Кладите их поверх текущей структуры (пути внутри
архива соответствуют путям в репозитории).

## Что изменилось

1. **Валюта**: доллары → рубли (`src/utils/format.js`, `FilterPanel.jsx`).
2. **Данные**: вместо `src/data/categories.js` и `src/data/vehicles.js`
   теперь используется Supabase (Postgres) — файлы `src/data/*` можно
   удалить после переноса, они больше не импортируются.
3. **Фото**: `Gallery.jsx` теперь показывает реальные фото (ссылки из
   Cloudinary), если они заданы у машины, иначе — прежний
   сгенерированный силуэт (для тех, у кого фото ещё не загружены).
4. **Стейджи**: `StagesList.jsx` больше не показывает прайс-лист
   апгрейдов, а показывает, что реально стоит на конкретной машине —
   список категорий: **База** (всегда первая) + до трёх из
   **Баланс / Скорость / Управление**.
5. **Аренда**: кнопка «Забронировать» теперь создаёт запись в таблице
   `rentals` в Supabase.
6. **Админка**: страница `/admin` — вход по общему паролю (SHA-256,
   проверка на сервере через Edge Function), CRUD для машин и
   категорий, управление стейджами конкретной машины, список аренд со
   статусами (активна / завершена / отменена).

## 1. Создать проект Supabase

1. Зайдите на supabase.com → New project.
2. В SQL Editor выполните целиком файл `supabase/schema.sql` из этого
   пакета — он создаст все таблицы, типы и политики RLS.

## 2. Установить пароль администратора

Пароль хранится не в открытом виде, а как SHA-256 хэш в таблице
`admin_config`. Посчитать хэш можно прямо в консоли браузера (F12 →
Console):

```js
const enc = new TextEncoder().encode('ваш-пароль-тут')
const buf = await crypto.subtle.digest('SHA-256', enc)
console.log(Array.from(new Uint8Array(buf)).map(b => b.toString(16).padStart(2, '0')).join(''))
```

Скопируйте получившуюся строку и вставьте в SQL Editor:

```sql
insert into admin_config (id, password_hash)
values (true, 'ВСТАВЬТЕ_СЮДА_ХЭШ');
```

## 3. Задеплоить Edge Functions

Понадобится Supabase CLI (`npm install -g supabase`).

```bash
supabase login
supabase link --project-ref <ваш-project-ref>

supabase functions deploy admin-login
supabase functions deploy admin-api
```

Секреты `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` Supabase
подставляет функциям автоматически — вручную задавать их не нужно.

Обе функции должны быть доступны анонимно (без Supabase Auth) — это
нормально: `admin-login` сама проверяет пароль, а `admin-api`
проверяет токен сессии на каждый запрос. Если при деплое CLI
предложит `--no-verify-jwt`, используйте этот флаг:

```bash
supabase functions deploy admin-login --no-verify-jwt
supabase functions deploy admin-api --no-verify-jwt
```

## 4. Настроить .env фронтенда

Скопируйте `.env.example` → `.env` и заполните:

- `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` — из Project Settings → API.
- `VITE_SUPABASE_FUNCTIONS_URL` — обычно
  `https://<project-ref>.functions.supabase.co`.
- Cloudinary-переменные — на будущее, если решите добавить загрузку
  фото прямо из админки (сейчас админка принимает уже готовые ссылки
  на фото, см. ниже).

## 5. Установить зависимость и перенести данные

```bash
npm install
```

(в `package.json` уже добавлен `@supabase/supabase-js`).

Дальше нужно перенести машины и категории из старых
`src/data/categories.js` / `src/data/vehicles.js` в таблицы Supabase.
Быстрее всего — вручную через админку (`/admin`): создать категории,
затем машины со стейджами. Если машин много и хочется автоматом —
могу отдельно сделать одноразовый Node-скрипт миграции по образцу
ваших скриптов для OSNOVA (`upload-vehicle-images-to-cloudinary.mjs` и
т.п.) — просто скажите.

## 6. Фото машин (Cloudinary)

Сейчас проще всего:

1. Загружаете фото в Cloudinary вручную (или своим существующим
   скриптом, как в OSNOVA — через unsigned preset для браузера).
2. Копируете готовые `https://res.cloudinary.com/...` ссылки.
3. Вставляете их в поле «Ссылки на фото» в админке (`/admin` →
   Машины), каждая ссылка с новой строки, первая = обложка галереи.

Если позже понадобится загружать фото прямо из формы админки (без
похода в Cloudinary руками) — это отдельная, тоже вполне посильная
доработка (unsigned upload прямо из браузера), могу сделать по
аналогии с Vehicle Constructor.

## Как это всё работает вместе (коротко)

- **Публичные страницы** (`/`, `/category/:id`, `/car/:id`) читают
  `categories`, `vehicles`, `vehicle_stages` напрямую через anon-ключ
  Supabase — RLS разрешает анонимному ключу только `select`.
- **Бронирование** на странице машины делает `insert` в `rentals`
  напрямую через anon-ключ — RLS разрешает только `insert`, читать и
  менять чужие брони анонимный ключ не может.
- **Админка** (`/admin`) ничего не делает напрямую в Supabase.
  Сначала `admin-login` (пароль → SHA-256 → сверка с хэшем в БД →
  выдаётся временный токен на 12 часов). Дальше все CRUD-операции
  (машины/категории/стейджи/аренды) идут через `admin-api` с этим
  токеном в заголовке `x-admin-token` — сама функция работает через
  сервисный ключ Supabase (полный доступ в обход RLS), так что таблицы
  `admin_config` и `admin_sessions` вообще недоступны из браузера
  напрямую — это и есть тот самый «по-нормальному», а не хэш в JS-коде
  фронта.
